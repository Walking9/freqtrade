## 一、策略是什么

一句话：**在 4 小时级别的上升趋势里，1 小时级别突破 4 天最高价时做多；趋势走坏（4h 跌破 EMA50）或亏损 8% 时离场。仅做多、1x 杠杆，标的是 BTC/ETH/SOL 永续（现货也兼容，见第五节）。**

- **Regime（4h 信息框架）**：`close_4h > EMA200_4h` 且 `EMA50_4h > EMA200_4h` → 处于上升趋势才允许开仓。
- **入场（1h）**：收盘价突破过去 96 根（4 天）最高价 → 下一根开盘市价做多。
- **出场**：4h 收盘跌破 `EMA50_4h`（趋势转弱）→ 市价离场；或触发 -8% 硬止损。
- **反向过拟合设计**：全部为经典趋势跟踪结构（regime 过滤 + 突破 + 止损），参数仅 4 个且均为约定俗成的整数取值；
  已通过参数扰动测试（唐奇安 72/96/120、止损 -8%/-10%/-15%、进出场逻辑一致性）——收益位于平台区不敏感。

## 三、回测结果（诚实口径）

**口径说明**：Binance USDT 永续，1000 USDT 起始，`max_open_trades=3`（每笔约 1/3 仓位）、1x 杠杆、市价单；
已计入 0.05% taker 手续费（双边）与**历史资金费率**；未建模滑点（BTC/ETH/SOL 流动性极好，市价单滑点影响很小但实盘存在）。

## 四、如何使用

以下命令的工作目录均为 `/Users/luka/Project/freqtrade_src/freqtrade`。

### 1. 回测（当前网络环境下需要 testnet 补丁）

```bash
cd /Users/luka/Project/freqtrade_src/freqtrade
PYTHONPATH=/Users/luka/Project/freqtrade_src/ai_work/testnet_patch AI_TESTNET_PATCH=1 \
.venv/bin/freqtrade backtesting --config user_data/config_backtest_ai.json --userdir user_data \
    --strategy SteadyTrend --timerange 20200101-20250701 --cache none --breakdown month year
```

补丁只影响"交易对元数据"的获取来源，不影响价格/手续费/资金费数据。**换行后若你有可用线路，去掉 `PYTHONPATH=... AI_TESTNET_PATCH=1` 前缀即可。**

### 2. 模拟盘（dry-run，建议先跑 2~4 周）

先按第五节第 4 条改好配置，然后：

```bash
.venv/bin/freqtrade trade --config config.json --strategy SteadyTrend
```

Web 界面：http://127.0.0.1:8080（config 里已配置 api_server）。

### 3. 实盘

完成第五节全部注意事项后，把配置里 `"dry_run": true` 改为 `false`，填入 API key（只开合约交易权限，
**不要开提现权限**），用同一命令启动。建议先用小资金（例如计划仓位的 10~20%）跑 1~2 个月再逐步加仓。

## 五、注意事项（重要，请逐条阅读）

1. **回撤预期 15%~30%**：开发窗口最大回撤 17.1%，但同家族参数扰动版本出现过 27~32%。实盘请按"随时可能吃 20%+
   回撤"做仓位规划；用杠杆会等比放大回撤，**不要上杠杆**。
2. **低胜率（约 33%）是设计特性**：趋势策略靠少数大盈利单覆盖大量小亏损。连续 5~10 笔亏损属于正常，
   不要因此中断策略或手动干预——那会破坏策略的数学期望。
3. **不要调参**：参数已通过平台区测试；任何"再优化一下"都会引入过拟合，是实盘翻车的最常见原因。
4. **配置要求**（用你现有的 `config.json` 需改两处）：
   - `entry_pricing.price_side` 和 `exit_pricing.price_side` 都必须是 **`"other"`**（市价单的强制要求；
     你当前的 `config.json` 是 `"same"`，不改会直接报配置错误）。
   - 建议 `max_open_trades: 3`（回测口径；更少会更保守）。
5. **网络/区域问题（当前实际存在）**：Binance 对当前网络出口全部返回 451（已实测你订阅的 13 个节点全部被拒）。
   这**不只是回测问题**：实盘/dry-run 同样连不上 Binance。实盘前必须解决（换一条 Binance 不封锁的线路）。
   回测用的 testnet 补丁**严禁**用于实盘——它会让下单接口指向错误的环境（策略本身不含补丁逻辑，只要运行时不加
   `AI_TESTNET_PATCH` 环境变量即可，天然安全）。
6. **资金费率**：永续做多会随行情收到/支付资金费（回测已按历史数据计入）。长期持有趋势单的资金费影响已包含在回测里。
7. **只交易 BTC/ETH/SOL**：策略只在流动性最好的三大币上验证过。换成其它币种前必须重新回测（大概率不再稳健）。
8. **现货兼容**：策略仅做多，因此在现货模式下也能用（`trading_mode: "spot"`），但回测口径是永续；现货无资金费、无爆仓，
   体验会更温和。若用现货，请用现货数据重新回测确认。
9. **监控建议**：dry-run 起步；实盘后每周看一眼回撤与成交记录，连续大额偏离（如回撤 > 35%）再停下来检查环境问题
   （交易所故障、断网、滑点异常），而不是改策略。
10. **风险提示**：加密货币波动极大，历史回测不代表未来收益。请只用可承受损失的资金。本策略为工具，不构成投资建议。

## 六、常见问题

- **为什么几周都不开仓？** 正常。4h 趋势过滤在震荡/下跌市会长期空仓，这是策略控制回撤的核心机制（2022 年全年基本空仓）。
- **为什么刚开仓就止损了？** 突破失败是趋势策略的正常成本（约 16% 的交易以 -8% 止损结束）。胜率低但盈利单足够大。
- **回测和实盘为什么会有差异？** 滑点、手续费档位、资金费时点、行情精度等；本回测未建模滑点，实盘年化可能比回测略低几个点。
- **能不能加币种 / 改时间框架？** 不建议。策略的超额来源于"主流币 + 4h 趋势 + 1h 突破"这个组合，改动需要完整重验。
